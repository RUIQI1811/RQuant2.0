# RQuant 子智能体分工

本文件规定本项目的任务分配、交接和审查。先读根目录 `AGENTS.md`、`agent.md`；新增因子集再读
`docs/adding-factor-sets.md`。源码、配置、测试和清单决定当前事实，不在角色模板里冻结因子数量、模型名称或回测默认值。
当前用户要求和项目规则优先于技能中的通用流程；沿用已有授权，常规步骤不重复向用户确认。

## 1. 主智能体与角色

主智能体负责目标、架构、任务拆分、模型选择、冲突裁决、整合和最终验收。不得把这些职责层层外包给管理智能体。
角色是可复用职责，不是每次任务必须启动的完整团队。

| 角色名 | 何时使用 | 交付物 |
| --- | --- | --- |
| `rquant_explorer` | 调用链、数据流或修改边界不明确 | 真实文件/符号、调用路径、相关测试、约束、未知项 |
| `rquant_researcher` | 公式来源、论文方法或指定依赖版本需要查证 | 原始来源、版本/日期、定义与输入映射、缺口与不确定性 |
| `rquant_worker` | 范围和验收条件已明确的实现任务 | 最小改动、聚焦测试证据、修改文件、未验证范围 |
| `rquant_tester` | 需要独立复现、额外回归覆盖或运行证据核对 | 原问题复现、命令/解释器/结果、证据缺口 |
| `rquant_reviewer` | 实现后的需求符合性和代码质量审查 | 有文件/行号依据的缺陷、严重性、影响、修复或验证建议 |
| `rquant_quant_reviewer` | 因子、时点数据、筛选、训练、回测或相关共享算子发生变化 | 公式、时间可用性、样本外和成交语义的审查结论与证据 |

六个角色文件均位于 `.codex/agents/`，文件名与角色名一致，不覆盖 Codex 内置的 `explorer`、`worker`。
简单任务由主智能体直接完成；仅“涉及多个文件”不构成必须派发的理由。

## 2. 派发与并行边界

- 先判断是否有明确、独立且值得委派的产物。探索和外部文献查证可在边界清楚时并行。
- 所有写入任务串行：主智能体和子智能体不能同时写代码，也不能并行让多个实现者或测试编写者改文件。
  实现完成并固定审查范围后，再派发独立审查；审查期间不得修改其所审版本。
- 数值或研究语义改动需要量化审查。小而集中的改动可以由一个独立审查者同时承担代码与量化检查，
  明确给出两项结论；复杂改动可让两种审查并行，避免重复审同一项。
- 子智能体不得继续派子智能体，不得自行提交、推送、创建 PR、运行生产计算或扩大授权。
  需要在任务约定之外扩大文件范围、改变公共接口/数据结构/依赖或进行架构取舍时，报告主智能体处理。
  已明确授权的任务内步骤直接执行，不逐步返回确认。
- 并发上限以当前工具实际提供的能力为准；角色数量、已完成数量不代表同时运行数量。
  等待时继续可独立完成的工作，使用工具允许的有界等待，不频繁轮询或重复派发已完成任务。
- 模型和推理强度由主智能体按本次可用列表、任务复杂度和风险选择，不绑定某个账号套餐或固定模型。
  有限的检索、清晰的机械修改与数值算法/研究审查分开评估；不能只按单次价格决定能力。
  记录实际派发设置，只有派发成功才声称使用了该角色或模型。

## 3. 每次任务的六项约定

派发时提供独立、精简的任务说明，默认使用干净上下文；不要复制整个聊天或整份工程文档。
干净上下文仍需包含必要的原始约束和相关文件路径，不能用摘要丢掉精确公式、日期或数值契约。

1. **目标**：一个可检查的结果，说明角色。
2. **范围**：工作目录、允许写入的精确文件、只读范围，以及需保留的用户改动。
3. **上下文**：需求原文/任务说明路径、相关入口、已确定的接口、依赖和审查版本。
4. **约束**：本项目相关契约、禁止操作、已有授权与未授权的长任务。
5. **交付物**：代码/证据/报告位置，以及返回格式。
6. **验收标准**：需要证明的行为、应执行的聚焦验证、独立审查范围和仍需用户执行的工作。

例如移植因子时：任务目标是实现指定公式及对照测试；范围明确库文件与测试文件；公式原文和输入可用时间
作为约束随任务传递；共享算子、注册表和依赖变更须先报告主智能体，不由实现者顺手修改。

## 4. 返回与恢复

统一返回 `DONE`、`DONE_WITH_CONCERNS`、`NEEDS_CONTEXT` 或 `BLOCKED`，随后提供：

- 结论和修改文件，或只读调查/审查的实际范围；
- 关键证据的文件/符号/行号，或可追溯的原始公开来源；
- 实际执行的命令、解释器、通过/失败/跳过结果和产物位置；没有运行则写“未运行”；
- 已确认事实、推断、未验证事项及需要主智能体处理的决定。

`DONE` 只表示本子任务满足约定，不表示全项目、生产构建或真实样本外回测已经通过。
长报告保存为本任务独有文件，主对话只返回摘要和路径；不得打印凭据或把本地研究数据/日志传到外部服务。

多阶段任务沿用 Superpowers 的任务说明、报告和进度记录，不再建立第二套账本。
记录任务、负责人、状态、改动范围/审查版本、测试证据、未解决问题及裁决。
恢复时先核对记录和实际文件；修复优先继续原实现者，不能因上下文压缩重新派发全部已完成任务。
失败要明确记录；缩小、重试、换能力或由主智能体接手均可，但必须说明实际处理和剩余证据缺口。

## 5. 验证与独立审查

- Python 验证只使用本项目 `rquant` Conda 环境的 Python 3.11，并确认 `rquant.__file__` 指向当前 checkout。
- 实现者负责自己的聚焦测试。验证者仅在明确分配了补充/修复测试的写入任务时才能修改测试，不能修改产品代码
  来消除失败。只读测试执行也可能写缓存/临时文件，不应被表述为独立操作系统权限隔离。
- 审查者检查真实差异和必要调用点，不依赖实现者的自我评价。确认审查的是包含本任务未提交改动的实际版本，
  不能只看 `HEAD` 而漏掉工作区/暂存区差异；主智能体必须排除用户无关改动并提供精确审查包。
- 记录测试对应的代码版本与工作区差异。相同版本已有完整证据时，不让每个审查者重复跑完整测试。
  有具体疑点则运行聚焦验证；审查后改动影响了已验证行为，应重新验证相关部分。
- 提交前由主智能体统一确认 `python -m ruff check src tests` 和 `python -m pytest -q` 在 Python 3.11 下通过，
  报告失败、跳过和警告；不把第三方警告一律视为本次阻断缺陷，也不隐去它们。
- 审查发现按实际影响和可信程度排序，给出位置、问题、后果和验证/修复方法；推测不得写成确认缺陷。
  需求符合性和代码质量各有结论；量化审查另外说明四项可信性分别验证到什么程度。
- 影响正确性、数据安全或研究结论的未解决问题不得冒充“审查通过”。主智能体可以驳回误报，需留下理由和证据；
  留待处理的问题必须在交付中披露，不能用达到返工次数上限代替验收。

## 6. RQuant 量化审查清单

按实际改动选相关项，避免每次扩展成全工程审计。`agent.md`、当前源码/配置和测试是详细口径的来源。

1. **公式与输入**：公开定义/许可证可追溯；缺输入的项明确跳过；生产公式通过 KunQuant 和注册表接入；
   独立参考未被生产实现替代；检查单位、复权、VWAP、窗口/长历史、NaN/Inf/零方差和极值处理。
2. **当时可用**：首次公告时间而非报告期决定财报可用性；历史股票池/行业/成分按时点判断；停牌缺口不能伪造行情。
   截断历史重算时同时比较过去的数值和缺失掩码，必要时检查缩放不变性、停牌及退化输入。
3. **选择和训练**：标签、日历、purge 与拟合区间一致；按当前配置核对训练/验证/测试边界；全期筛选的方向、
   权重、相关性或覆盖率信息是否影响历史测试。滚动训练本身不能消除预先使用全期数据的选择偏差。
4. **可交易性**：按当前实现检查次日开盘、T+1、100 股买入单位、停牌/涨跌停、费用、换仓周期及期末未卖出持仓。
   IC、多空分组和候选挖掘期的表现不能代替受约束的 long-only 样本外结论。
5. **可复用与可审计**：因子目录、实现/编译指纹、标准数据与实际参考输入内容哈希、股票池和日期范围匹配；
   `factors validate` 通过不替代实现指纹比较；用 `run.json` 状态、日志和约定输出核实运行结果。

数据同步、参考数据构建、因子构建/验证/评估、训练和报告等操作仍受 `agent.md` 与用户授权约束。
角色派发不新增这些权限；未具备 token/必要数据时不启动受限制任务。
尤其 `factors build --start/--end` 会替换同名完整因子目录，不能当作无害的小范围诊断。

## 7. Codex 接入与兼容

- 本项目仅提供角色定义，不新增全局设置、固定模型、权限模式或 MCP 服务。
  角色的 `developer_instructions` 是行为约定，不构成独立权限隔离；权限、服务连接由父会话控制。
- 若当前 Codex 接口支持选择自定义角色，使用对应名称并核对实际结果；否则读取对应 TOML，
  把其中 `developer_instructions` 与六项任务约定一起交给通用子智能体。
  记录为“显式角色提示词派发”，不能宣称已验证按名自动加载或模型路由。
- 若没有子智能体工具，主智能体完成可独立推进的工作，并明确独立审查尚未发生。
  同一作者的自检不能标记成独立审查；需要的独立审查未完成时不得宣称该验收项通过。
- 后续修改项目角色时检查 TOML 可解析、名称唯一、必需字段齐全、文档/角色引用存在，
  并用实际派发情景核对边界遵守情况；语法检查不能证明模型路由、权限或行为可靠性。
