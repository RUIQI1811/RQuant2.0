# QMT 内置策略（国金证券实盘，方案 C）

2026-10-23 起，券商升级后的 QMT 内置 Python 策略不能读写本地文件，也不能发起任何网络连接；miniQMT/xtquant 外接也在关闭。
所以 RQuant 的信号不能从外部送进 QMT，选股逻辑必须整体在 QMT 沙箱里运行，只用 QMT 自带的行情和财务数据。
本目录放要粘贴进 QMT 的策略文件。它们不属于 `rquant` 包，也不在 `rquant` 环境里运行。

## 规则

- 账号、密码、资金账号只在 QMT 客户端里配置，不写进本仓库的任何文件。
- 带下单功能的策略，必须先在 QMT 模拟或纸面运行中通过，并经用户明确确认后，才能接实盘账户。
- 策略文件只用 ASCII 字符（中文写成 `\uXXXX`），并且兼容 Python 3.6 语法，这样 QMT 编辑器用 GBK 还是 UTF-8 都不影响。

## 第 1 步：环境探测（`probe_env.py`，只读）

这个策略不下单、不查委托、不读写文件、不联网，只把沙箱能提供什么打印到日志里：

- Python 版本，以及 numpy、pandas、lightgbm、talib 等库能不能 import；
- 上证 A 股、沪深 300 股票列表；全部沪市主板 320 个交易日日线的取数耗时，以及前复权、后复权两种口径；
- 合约信息（名称/ST、上市日、流通股本、涨跌停价）和换手率接口；
- 财务数据接口能用哪些字段写法，能否按公告日取值（point-in-time）；
- 用 numpy 跑一个和 jq240 LightGBM 规模相当的模拟树模型（500 棵树、深度 6、240 个特征），给 1700 只股票打分要多久；
- 内存占用（有 psutil 时）。

运行方法：

1. 打开国金 QMT，登录后进入「数据管理 → 补充数据」，补充「沪深A股」日线，起始日期选 2010-01-01（至少覆盖最近两年）。
2. 在「我的策略」里新建 Python 策略，把 `probe_env.py` 的全部内容粘贴进去，保存。
3. 主图选 `000300.SH`，周期选「日线」，点「运行」。不要点「实盘交易」，这个脚本也不会下单。
4. 在日志窗口里，把所有以 `[RQ]` 开头的行复制出来发回给我，截图也可以。

## 第一次探测结果（2026-11-03，国金 QMT 装在 `D:\国金证券QMT交易端`）

- 内置 Python 是 3.6.8，**没有 numpy、pandas 等任何第三方库**；设置里的「Python库下载」报「未知的错误」，换安装位置、用管理员身份都一样。
- `get_history_data` 不依赖 pandas，可以取到沪市主板 1700 只股票 320 天的开高低收、成交量、成交额，每个字段 3–9 秒。
  不复权和前复权的收盘价最近几天返回 -1，后复权正常。
- `get_market_data_ex`、`get_financial_data`、`get_turnover_rate` 都依赖 pandas，目前用不了。所以财务数据暂时取不到，jq240 搬不进去。
- QMT 用 GBK 保存策略文件，文件头要写 `#encoding:gbk`，写 `# coding: utf-8` 会编译失败。
- QMT 装在 `Program Files` 下时，非管理员身份无法保存或编译改过的策略。
- 国金 2026-10-24 的通知说，2.1.33.0 版客户端支持 Python 3.12。下一步先拿这个版本，确认它是否自带 numpy 和 pandas。

## 后续步骤

1. 根据探测结果，列出 jq240 中能用 QMT 数据算出来的因子，并离线回测“只用这些因子”的模型，量化损失多少。
   如果 jq240 大部分搬不进去，备选是 Alpha158：它只用日线 OHLCV，在 sh_main 上 LGB 1d 年化 17.2%、Sharpe 0.71。
2. 把训练好的 LightGBM 模型导出成纯 numpy 数组，和因子计算一起生成一个单文件 QMT 策略。
   在仓库里加对齐测试，确保同一份行情下，QMT 版本的打分和 pipeline 的打分一致。
3. 在 QMT 模拟账户或纸面模式下运行（只记日志、不下单），连续两周和回测持仓对比。
4. 用户确认后，再小资金接实盘：top50、每天最多换 5 只，开盘集合竞价附近限价下单，带单票金额上限和数据过期保护。
