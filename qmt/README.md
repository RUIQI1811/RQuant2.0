# QMT 内置策略（国金证券实盘，方案 C）

2026-10-23 起，券商升级后的 QMT 内置 Python 策略不能读写本地文件，也不能发起任何网络连接；miniQMT/xtquant 外接也在关闭。
所以 RQuant 的信号不能从外部送进 QMT，选股逻辑必须整体在 QMT 沙箱里运行，只用 QMT 自带的行情和财务数据。
本目录放要粘贴进 QMT 的策略文件。它们不属于 `rquant` 包，也不在 `rquant` 环境里运行。

## 规则

- 账号、密码、资金账号只在 QMT 客户端里配置，不写进本仓库的任何文件。
- 带下单功能的策略，必须先在 QMT 模拟或纸面运行中通过，并经用户明确确认后，才能接实盘账户。
- 策略文件只用 ASCII 字符（中文写成 `\uXXXX`），并且兼容 Python 3.6 语法，这样 QMT 编辑器用 GBK 还是 UTF-8 都不影响。

## 第 1 步：环境探测（`probe_env.py`，只读）

这个策略不下单、不查委托、不读写文件、不联网，只把沙箱能提供什么打印到日志里：

- Python 版本，以及 numpy、pandas、lightgbm、talib 等库能不能 import；
- 上证 A 股、沪深 300 股票列表；全部沪市主板 320 个交易日日线的取数耗时，以及前复权、后复权两种口径；
- 合约信息（名称/ST、上市日、流通股本、涨跌停价）和换手率接口；
- 财务数据接口能用哪些字段写法，能否按公告日取值（point-in-time）；
- 用 numpy 跑一个和 jq240 LightGBM 规模相当的模拟树模型（500 棵树、深度 6、240 个特征），给 1700 只股票打分要多久；
- 内存占用（有 psutil 时）。

运行方法：

1. 打开国金 QMT，登录后进入「数据管理 → 补充数据」，补充「沪深A股」日线，起始日期选 2010-01-01（至少覆盖最近两年）。
2. 在「我的策略」里新建 Python 策略，把 `probe_env.py` 的全部内容粘贴进去，保存。
3. 主图选 `000300.SH`，周期选「日线」，点「运行」。不要点「实盘交易」，这个脚本也不会下单。
4. 在日志窗口里，把所有以 `[RQ]` 开头的行复制出来发回给我，截图也可以。

## 第一次探测结果（2026-11-03，国金 QMT 装在 `D:\国金证券QMT交易端`）

- 内置 Python 是 3.6.8，**没有 numpy、pandas 等任何第三方库**；设置里的「Python库下载」报「未知的错误」，换安装位置、用管理员身份都一样。
- `get_history_data` 不依赖 pandas，可以取到沪市主板 1700 只股票 320 天的开高低收、成交量、成交额，每个字段 3–9 秒。
  不复权和前复权的收盘价最近几天返回 -1，后复权正常。
- `get_market_data_ex`、`get_financial_data`、`get_turnover_rate` 都依赖 pandas，目前用不了。所以财务数据暂时取不到，jq240 搬不进去。
- QMT 用 GBK 保存策略文件，文件头要写 `#encoding:gbk`，写 `# coding: utf-8` 会编译失败。
- QMT 装在 `Program Files` 下时，非管理员身份无法保存或编译改过的策略。
- 国金 2026-10-24 的通知说，2.1.33.0 版客户端支持 Python 3.12。下一步先拿这个版本，确认它是否自带 numpy 和 pandas。

## 模型导出与打分（`export_model.py`、`runtime/lgb_numpy.py`）

QMT 里没有 lightgbm，所以把 walk-forward 某一年窗口的 LightGBM 导出成 JSON，在 QMT 里用 numpy 打分。

- 在 Windows 上，从仓库根目录运行（需要 rquant 环境）：
  `python qmt/export_model.py --run runs/walk-forward/<run> --year 2026 --store data/factors-sh_main/jq240 --out qmt_model_2026.json`
- 导出文件包含因子名顺序、该窗口训练期的 ZScoreNorm 均值和标准差（按训练方式从因子库重新计算，每次 16 列，峰值约 1.1 GB），以及展平后的树。
- 导出后会自检：用 numpy 给最后一天打分，再和 booster 以及回测保存的预测对比，两项都必须完全相同才打印 OK。
- 把导出的 JSON 放到 `qmt/models/lgb_jq240_sh_main.json`，然后运行 `python qmt/build_jq240.py`，模型就会写进生成的策略。
- 2026 年窗口（run `20261101T210410Z-aada1bdd`，训练期 2023-01-03..2025-12-30）只有 8 棵树，所以很多股票分数相同。

## 一致性核对（`generated/jq240_parity.py`）

在 QMT 里按 `AS_OF` 那一天计算全部 jq240 因子和模型打分，打印出来后与 Windows 因子库、回测预测比对。
2026-10-21 的核对结果：QMT 算出的 top10、top20、top30、top50 和回测完全相同，96% 的分数逐位一致。
QMT 没有折旧摊销数据，所以 EBITDA 实际等于 EBIT；营业总成本不含减值损失。这两个因子在模型里的重要性约为 0.1%。

## 每日模拟盘（`generated/jq240_paper.py`，只打印，不下单）

每天收盘后运行一次。脚本会计算从 `PAPER_START` 到最新交易日的每天打分，再用 `PAPER_CAPITAL` 现金从头重放模拟盘：
top `PAPER_TOPK`、每天最多换 `PAPER_N_DROP` 只、次日开盘价成交、A 股佣金（最低 5 元）和印花税、100 股取整、
停牌和开盘涨跌停不能成交。规则和 RQuant 回测里的 Qlib TopkDropoutStrategy 一致。
持仓不需要存文件，每次运行时重新推算出来。

运行时间：北京时间收盘后到第二天开盘前（美西时间大约晚上 11 点半以后到第二天下午 5 点前）。
盘中运行时，QMT 已把今天列进交易日历，但今天的日线还没有，脚本会跳过今天并打印 `paper.skipped_days`；
这时 `paper.next.*` 是昨天收盘后的计划，今天开盘已经过了，没有参考价值。

日志里会打印：

- `paper.fill.<日期>`：每天的模拟成交；
- `paper.nav.<日期>`：每天的模拟盘净值；
- `paper.hold`：当前持仓；
- `paper.next.sell`、`paper.next.buy`：下一个开盘要卖和要买的股票（按今天收盘价估算股数）；
- `paper.next.backups`：备选股票，用于计划买入的股票开盘涨停时替补。

模拟盘逻辑和回测对比过：以 2026 年 189 个交易日为例，每天都从回测当天的真实持仓出发，用模拟盘逻辑计算成交和净值。
所有不一致都出在同分股票先选哪一只上。Qlib 用不稳定排序，同分股票谁在前取决于 numpy 的版本；模拟盘改成同分时按股票代码排序。

## 实盘策略（`generated/jq240_live.py`，自动下单）

每个交易日北京时间 9:15 前在 QMT 实盘交易模式下启动（选好资金账号）。启动后先用上一个交易日的数据打分（约 8 分钟）。
9:30:05 读真实持仓、现金和开盘价，按回测同样的 TopkDropout 规则卖出；9:30:25 用当时的可用资金买入。
都用可立即成交的限价单（最新价上下 1%，不超过涨跌停价）。每天最多下一次单，10:00 以后不再下单。
同一天已经发过带 `RQ<日期>` 备注的委托就不会再发。

- `LIVE_DRY_RUN = True`（默认）：只打印 `live.dry_sell` / `live.dry_buy`，不下单；非交易时间运行会立刻用当前行情演练一遍。
- `LIVE_ACCOUNT`：留空时用策略里选的账号；只在 QMT 编辑器里填，不要提交到仓库。日志只显示账号后 4 位。
- `LIVE_CAPITAL`：策略最多占用的资金（持仓市值加可用现金）；只管理 60 开头的上证主板股票，`LIVE_KEEP` 里的不动。
- 数据不是最新（上一个交易日的日线没有）时不下单，并提示先补充数据。

   如果 jq240 大部分搬不进去，备选是 Alpha158：它只用日线 OHLCV，在 sh_main 上 LGB 1d 年化 17.2%、Sharpe 0.71。
