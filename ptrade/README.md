# PTrade 实盘（国金证券，jq240 + LightGBM）

2026-11-11 起实盘从 QMT 迁到国金 PTrade。PTrade 的策略跑在券商服务器上，电脑关机也照常运行。
服务器上是 Python 3.11、numpy 1.23、pandas 1.5，没有 lightgbm，所以和 QMT 一样用 `qmt/runtime/lgb_numpy.py` 打分。
本目录的文件都由 `python qmt/build_jq240.py` 生成或打包，不属于 `rquant` 包。

## 规则

- 账号、密码只在 PTrade 客户端里登录，不写进本仓库的任何文件。日志里账号只显示后 4 位。
- `LIVE_DRY_RUN = True`（默认）只打印不下单。只有用户自己看过模拟输出后，才在 PTrade 里改成 `False`。
- PTrade 研究模块禁止 `os`、`sys` 等系统模块；生成的文件不含这些词，构建脚本会检查。

## 文件

| 文件 | 用途 |
| --- | --- |
| `probe_research.py` | 研究模块里跑的只读探测（库版本、取数接口和耗时） |
| `runtime/ptrade_inputs.py` | 用 PTrade 自带数据拼出 jq240 的输入（与 QMT 适配器口径一致，测试对齐） |
| `runtime/research_parity.py` → `generated/jq240_research_parity.py` | 研究模块里的对账：给定日期的 top30 |
| `runtime/ptrade_live.py` → `generated/jq240_ptrade_live.py` | 实盘策略（交易模块） |

实盘策略的下单规模和 QMT 完全是同一份代码：构建时从 `qmt/runtime/live_shell.py` 取出 `live_sell`、`live_buy`，
只把账户、行情快照、下单这几个接口换成 PTrade 的（`context.portfolio`、`get_snapshot`、`order`）。

## 对账结果（2026-11-12）

研究模块里用 2026-11-10 的数据打分，top30 与 QMT 11-11 实盘日志的 `live.top30` 是同一组股票（只有同分股票的先后不同）。
冷启动 1100 个交易日的输入要约 19 分钟，主要花在逐日的估值和 ST 状态查询上。
`jq_029`、`jq_051`（固定资产）曾经全空：PTrade 三季报的 `fixed_assets` 是空的，现在空时改用 `total_fixed_asset`（2026-11-12 修复）。

## 实盘策略的时间表（北京时间）

- 打分（`LIVE_PLAN_AT`）：启动时、前一天 21:00、当天 08:00/08:30，以及 09:00 到 09:42 每两三分钟一次。手里的打分已经用上最近一个交易日的数据就跳过。
  PTrade 前一交易日的日线要到 09:10 左右才有（2026-11-13、11-17 都是 09:05 还缺，09:12 前到），
  所以早上每次先抽查 40 只股票的日线（约 1 秒），到了才打分。21:00 那次给前一个交易日打分，顺便把估值、ST、
  市场收益和财报数据存进内存；第二天早上只补新的一天，约 4 分钟打完。新建交易后的第一次约 20 分钟。
- 09:21（`LIVE_AUCTION_AT`，打分晚了 09:23 再试一次）：集合竞价下单。卖单挂跌停价，买单最高挂昨收 +3%，开盘价成交。
  买单只用竞价前的现金，并留出约 `LIVE_N_DROP` 份现金给第二天的竞价买入。
- 09:31 / 09:40 / 09:50 卖，各自 1 分钟后买：只有竞价时计划还没好才用，开盘后先卖后买，挂最新价 ±1%；已经卖过就不再卖，10:00 以后不下单。
- 打分结果同时存进 `g`（PTrade 重启后会恢复）。券商重启交易后直接用存下的打分，不用再冷启动 20 分钟。
- 每天最多交易一次；账户当天已经有沪市主板委托（比如服务器重启后），当天就不再下单。
- 参数与 QMT 相同：top30、每天最多换 3 只、`LIVE_TOPUP = False`（闲钱只给当天新买的股票，每只最多 1.3 份）。
- 2026-11-18 起另加 `LIVE_EXIT_RANK_PCT = 0.7`：持仓当天排名跌出全部 sh_main 打分股票前 70% 的，不受每天 3 只的限制全部卖出并补上
  （回测 `x70`，见 `docs/score-rules.md`；QMT 版仍是 `None`）。设成 `None` 就回到原来的规则。

## 使用步骤

1. 停掉 QMT 里的实盘策略，避免两边同时下单。
2. PTrade → 量化 → 新建策略（股票、日线），把 `generated/jq240_ptrade_live.py` 全部粘贴进去，保存。
3. 新建交易，选这个策略启动。日志里会马上出现 `[RQ] live.top30=...` 和一组 `live.dry_sell` / `live.dry_buy`。
4. 第二天 09:21 再看一次模拟下单。确认没问题后，把 `LIVE_DRY_RUN = True` 改成 `False`，重新启动交易。

持 50 只、每天最多换 5 只，不用跌出前 70% 就卖（回测 `main-blend-jq240-size_value_china`，20 万从 2020 年起
年化 28.9%、Sharpe 1.01）。由 `python ptrade/build_main_blend.py` 生成：

| 文件 | 用途 |
| --- | --- |
| `runtime/svc_inputs.py` | 用 PTrade 全 A 股日线和估值表算 CH-3/CH-4 因子收益（`CH4FactorBuilder`），拼 size_value_china 的输入、打分、合并 |
| `runtime/main_parity.py` → `generated/main_blend_research_parity.py` | 研究模块对账：AS_OF 2026-10-21 的两个模型和合并分数，和回测逐只比 |
| `runtime/main_live.py` → `generated/main_blend_ptrade_live.py` | 实盘策略：`ptrade_live.py` 设成 `LIVE_UNIVERSE = "main"`、top50、换 5，打分换成合并分数 |

- 模型：`qmt/models/lgb_jq240_main.json`（32 棵树）和 `qmt/models/lgb_size_value_china_main.json`（13 棵树），都是 2026 年窗口
  （训练 2023-01-03 至 2025-12-30），导出时和回测预测逐位相同。合并：两个模型的分数每天各自标准化（ddof 1）后等权平均，只用两个都打了分的股票。
- size_value_china 读 Tushare daily_basic 的单位：`total_mv` 是万元（PTrade 市值 / 1e4），`pe_ttm` 用和 jq240 一样的
  市值 / 归母净利润 TTM，`turnover_total` 是成交股数 / 总股本。CH-4 因子收益用全 A 股（60、00、30 开头，含创业板，和论文一致）
  每天的收盘/昨收、总市值、估值表的 `pe_ttm` 和换手率，按月分组，需要约 530 个交易日的全 A 股数据。
- 上线步骤：先在研究模块跑对账文件，看三个 `compare.*.rank_corr` 和 `top50_overlap`；通过后跑几天只打印的实盘文件，再由用户决定真实下单。
